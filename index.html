Daily Dev Digest Workflow

n8n workflow, kuris automatiškai paleidžiamas pagal nustatytą laiką, pasiima naujienas ir postus iš tavo RSS feed'ų, o tada naujausiu Gemini modeliu juos įvertina ir paruošia dienos suvestinę - naudingą kaip tik todėl, kad neapkrauna tavęs pertekline informacija. Žinutė nesiunčiama iš karto: n8n sukuria Draft'ą Gmail'e, kad galėtum peržiūrėti ir patvirtinti prieš siunčiant.

20-30 min n8n Cloud Gmail OAuth2 (draft'ams)
Trigger Feed pipeline AI pipeline

Ką išmoksi padaryti

Ko išmoksi

  • ✓Susikurti postų šaltinių sąrašą su Set node'u. Taip pat naudojamas Split Out - jis iškaido didelį sąrašą į atskirus item'us, todėl galime parsisiųsti daugiau postų lygiagrečiai. Naujo šaltinio pridėjimas niekada nereiškia naujo node'o.
  • ✓Paaiškinti n8n per-item vykdymo modelį: kai node'as gauna kelis item'us, jis savo logiką paleidžia atskirai kiekvienam iš jų, o gautus rezultatus vėl sujungia į vieną sąrašą.
  • ✓Sukuriamas AI prompt'as, pagal kurį vertinami post'ai naudojant naujausią Gemini modelį, o rezultatai grąžinami pagal JSON schemą.
  • ✓Vien AI modelio atsakymo neužtenka - jį reikia išparsinti (parse), kad ilgas modelio grąžintas tekstas virstų struktūrizuotais duomenimis, kuriuos vėliau galime panaudoti tolimesniuose workflow žingsniuose.
  • ✓Išmokti, kaip gautus rezultatus siųsti paštu, pvz., per Gmail. Sukursime Draft, kurį dar galima pataisyti, o žmogus pats nuspręs, siųsti ar ne - human in the loop.

Prieš pradedant

Keturi dalykai, kuriuos gera žinoti

Vykdymas kiekvienam item'ui

Node'as savo darbą atlieka atskirai su kiekvienu item'u, kurį gauna. Trys items įeina - trys fetch'ai išeina, iš vieno node'o.

Sąrašo išskaidymas

Split Out paverčia vieną item'ą su sąrašu į kelis atskirus item'us. Pvz., 1 item su 5 RSS post'ais taps 5 items - po vieną kiekvienam post'ui.

Modelio connector'is

Basic LLM Chain node'as leidžia prisijungti bet kurį palaikomą LLM modelį, kaip kad Claude, OpenAI ar Gemini. Naudojame Gemini dėl patogumo, bet galite lengvai pakeisti - per modelio connector'į.

Pasitikėk, bet patikrink

Modeliui verta duoti kuo mažiau autonomijos - jis gali haliucinuoti. Rūšiavimą, skaičiavimus ir kitą duomenų apdorojimą patikimiau atlikti kodu (JavaScript ar Python), o ne prašyti to iš modelio promptu. Šis workflow modeliu pasitiki tik įvertinimui - o rūšiavimą vis tiek tyliai perdaro kode.

Galutinis rezultatas

Visas pipeline'as, iš paukščio skrydžio

Aštuoni node'ai, viena grandinė: nuo suplanuoto trigerio iki paruošto Gmail draft'o. Kiekvienas node'as atlieka vieną aiškią užduotį, o duomenys per juos teka be jokio rankinio įsikišimo.

Kūrimo eiga, node po node

Aštuoni node'ai, vienas pipeline'as

Sek žingsnius eilės tvarka, vieną po kito.

01Trigger

Pridėk trigerį - Schedule Daily

Schedule Trigger
Triggers the workflow on a given schedule
  1. Pridėk Schedule Trigger node'ą. Pervadink jį į Schedule Daily.
  2. Palik trigerio taisyklę numatytajame Interval režime ir nustatyk Trigger at Hour reikšmę į 8.
Kodėl

Kiekvienas workflow turi būti kažkaip paleidžiamas - kito kodo, tam tikru laiku, kito agento arba rankiniu būdu (pvz., Execute Workflow). Kitaip jis niekada nepasileis. Čia pasirenkame laiką: Interval režimas su valanda 8 tiesiog reiškia „vykdyk kiekvieną dieną 8 val. ryto“.

Checkpoint

Node'as rodo Interval režimą su Trigger at Hour nustatytu į 8, be klaidų.

02Feed pipeline

Susikurk feed'ų sąrašą - List of RSS Feeds

Edit Fields (Set)
Modify, add, or remove item fields
  1. Pridėk Edit Fields (Set) node'ą po Schedule Daily. Pervadink jį į List of RSS Feeds.
  2. Pridėk vieną lauką pavadinimu urls, nustatyk jo Type į Array, su reikšme:
urls (array)["https://dev.to/feed/tag/python", "https://dev.to/feed/tag/ai", "https://dev.to/feed/tag/productivity"]
Kodėl

Šis laukas atsako į klausimą „iš kokių šaltinių imu duomenis“. Naudojame tokį sprendimą, kad vėliau galėtume pridėti dar 5 linkus - tiesiog papildant šį lauką, be pasikartojimo ir be kodo keitimo.

Checkpoint

json.urls turi būti array su 3 elementais, ne tekstinė eilutė.

03Feed pipeline

Išskaidyk sąrašą - Split Out

Split Out
Turn a list inside item(s) into separate items
  1. Pridėk Split Out node'ą po List of RSS Feeds.
  2. Nustatyk Field to Split Out į urls.
Kodėl

Turėjome 1 item'ą su 3 URL sąraše. Split Out jį paverčia į 3 items - po vieną kiekvienam URL. Tada tolimesni node'ai kiekvieną apdoroja atskirai, patys.

Checkpoint

Testuojant grąžinami 3 atskiri items, kiekvienas su json.urls kaip viena URL eilutė.

04Feed pipeline

Parsisiųsk kiekvieną feed'ą - Retrieve Post Data

RSS Read
Reads data from an RSS Feed
  1. Pridėk RSS Feed Read node'ą po Split Out. Pervadink jį į Retrieve Post Data.
  2. Nustatyk URL į {{ $json.urls }}.
  3. Node'o nustatymuose įjunk Retry On Fail, Wait Between Tries 3000 ms.
Kodėl

Čia ir pasireiškia n8n per-item vykdymas: node'as gavo 3 items, todėl fetch'ą atlieka 3 kartus, po vieną kiekvienam URL - be jokio papildomo node'o.

Checkpoint

Testuojant grąžinama daug items, kiekvienas su title, link, pubDate, content arba contentSnippet.

05Feed pipeline

Išvalyk ir sujunk į vieną - Parse RSS data

Code
Run custom JavaScript or Python code
  1. Pridėk Code node'ą po Retrieve Post Data. Režimas: „Run Once for All Items“.
Parse RSS data - Code node// Ši funkcija išvalo teksto lauką nuo HTML žymių
function clean(raw) {
  if (!raw) return '';
  let text = String(raw);
  text = text.replace(/<(script|style|pre)[^>]*>[\s\S]*?<\/\1>/gi, ' ');
  text = text.replace(/<\/?(p|div|li|h[1-6]|br|tr|blockquote)[^>]*>/gi, '\n');
  text = text.replace(/<[^>]+>/g, '');
  return text.trim();
}

// Kiekvienam gautam item'ui paliekame tik reikalingus, jau išvalytus laukus
const items = $input.all().map(item => ({
  title: clean(item.json.title),
  creator: item.json.creator || item.json['dc:creator'] || '',
  link: item.json.link,
  pubDate: item.json.isoDate || item.json.pubDate,
  categories: item.json.categories || [],
  content: clean(item.json.content),
}));

// Sutraukiame viską į VIENĄ item'ą, kad kitas žingsnis matytų visą sąrašą iš karto
return [{ json: { count: items.length, items } }];
Kodėl sutraukti į vieną item'ą

Modeliui reikia visų straipsnių vienu prompt'u, kad galėtų juos palyginti ir surikiuoti.

Po dangčiu

Dublikatų čia sąmoningai neieškome pagal URL - tai paliekame AI, nes ji atpažins ir panašias, ne tik identiškas, istorijas.

Checkpoint

Vienas item'as su json.count ir json.items - išvalyti straipsnių objektai.

06AI pipeline

Įvertink ir sudaryk suvestinę su Gemini - Digest & Scoring LLM

Basic LLM Chain
A simple chain to prompt a large language model
  1. Pridėk Basic LLM Chain node'ą. Prijunk Google Gemini Chat Model node'ą per modelio connector'į (jungiasi iš apačios, ne iš šono). Prijunk credentials ir aiškiai pasirink modelį.
  2. Nustatyk Prompt (User Message) į „Define“ režimą:
You are a technical newsletter editor. You will receive a JSON array of blog/RSS posts (fields: title, creator, link, pubDate, categories, contentSnippet). Your job is to produce a digest. Score each post from 0-100 on overall digest-worthiness, using this rubric: - Relevance (0-40): how useful/novel to the audience - Depth (0-25): does it teach something concrete vs. surface-level/listicle - Timeliness (0-15): recency and whether it references current tools/versions - Actionability (0-20): does it give something concrete to do (working code, a runnable example, specific steps) vs. just conceptual discussion. Good if the digest is for practitioners who want to apply things. Deduplicate near-identical stories (same news covered by multiple posts) - keep the best one and note the count of duplicates in "duplicate_count". Return ONLY valid JSON matching this schema, no prose outside the JSON: { "intro": "1-2 sentence summary of the overall theme(s) across today's posts", "top_stories": [ { "title": "string", "link": "string", "creator": "string", "score": 0-100, "score_reason": "one short phrase, e.g. 'deep dive, high relevance'", "summary": "1-2 sentence plain-language summary of what it covers and why it matters", "categories": ["string"], "duplicate_count": 0 } ], "all_stories": [ /* same shape as top_stories, every input item, sorted by score descending */ ] } "top_stories" = only items scoring 70+, max 5. "all_stories" = every item, for full sortable output. Here are today's posts ({{ $json.count }} total): {{ JSON.stringify($json.items) }} Generate the digest per the schema and rubric.
  1. Node'o nustatymuose įjunk Retry On Fail, Max Tries 2, Wait Between Tries 5000 ms.
Kodėl scoring rubrika

Vietoj neapibrėžto „įvertink nuo 1 iki 10“, duodame modeliui keturis konkrečius kriterijus iki 100 balų. Rezultatas - stabilesni įvertinimai tarp skirtingų paleidimų, net jei schema grąžina tik bendrą sumą.

Checkpoint

Sėkmė - modelis grąžino text lauką, kurį kitame žingsnyje parsinsime į tvarkingą formatą.

07AI pipeline

Apdorok AI atsakymą, paruošk laišką - Parse LLM Output

Code
Run custom JavaScript or Python code
  1. Pridėk Code node'ą po Digest & Scoring LLM.
Parse LLM Output - Code node// Ši funkcija nuvalo modelio atsakymą (pvz., ```json žymes) ir paverčia į tikrą JSON
function parseDigest(raw) {
  let str = String(raw).trim();
  str = str.replace(/^```(?:json)?\s*/i, '').replace(/```\s*$/i, '');
  return JSON.parse(str);
}

// Paimame modelio atsakymą - lauko pavadinimas gali skirtis, tad tikriname kelis variantus
const item = $input.all()[0];
const raw = item.json.text ?? item.json.output ?? item.json;
const digest = typeof raw === 'string' ? parseDigest(raw) : raw;

// Saugiklis: perrūšiuojame straipsnius pagal balą, jei modelis to nepadarė pats
const allSorted = [...digest.all_stories].sort((a, b) => b.score - a.score);

// Sudedame galutinį laišką - temą, HTML ir tekstinę versiją
return [{
  json: {
    subject: `Dev Digest - ${digest.top_stories.length} top stories, ${allSorted.length} total`,
    html /* built from digest + allSorted */,
    text /* plain-text version */,
  }
}];
Kam reikalingas šis node'as

Modelis grąžina tekstą, o ne tvarkingą laišką - šis node'as jį paverčia į paruoštą subject, HTML ir tekstinę versiją. Papildomai jis pats dar kartą surikiuoja straipsnius pagal balą, kad laiško tvarka būtų teisinga, net jei modelis suklystų.

Checkpoint

Vienas item'as su subject, html, text, topStoryCount, totalCount. html turi tavo tikrus pavadinimus, įvertinimus ir nuorodas.

08Delivery

Sukurk Gmail draft'ą - Create Digest Draft

Gmail
Fetches emails from Gmail and starts the workflow on specified polling intervals
  1. Pridėk Gmail node'ą. Nustatyk Resource į Draft (ne Message/Send).
  2. Nustatyk Email Type į HTML, Message į {{ $json.html }}.
  3. Options → Send To įrašyk savo adresą. Prijunk Gmail OAuth2 credentials.
Kodėl draft'as, ne send'as

Tai human in the loop - modelis paruošia laišką, bet žmogus jį peržiūri prieš išsiunčiant. Taip išvengiama situacijos, kai blogai suformuotas ar klaidingas AI laiškas iškart nukeliauja pas gavėją. Kai jau pasitiki suvestine, perjungimas iš Draft į Send yra vieno mygtuko paspaudimas.

Checkpoint

Po pilno test paleidimo tavo Gmail Drafts aplanke (ne Inbox) atsiranda naujas draft'as su pataisytu dinaminiu subject ir suformatuotu HTML turiniu.

Pilnas paleidimas

Testuok visą pipeline'ą

Paspausk Test workflow ir stebėk, kaip kiekvienas node'as užsidega eilės tvarka:

Schedule Daily → List of RSS Feeds → Split Out (3 items) → Retrieve Post Data → Parse RSS data → Digest & Scoring LLM → Parse LLM Output → Create Digest Draft

Atsidaryk Gmail Drafts aplanką ir patikrink, ar draft'as sukurtas, subject atspindi tavo Step 8 pataisymą, o HTML turinys parodo realius straipsnius su veikiančiomis nuorodomis. Jei kuris nors node'as šviečia raudonai - paspausk jį, klaidos panelė nurodys, kuri išraiška nepavyko.

Kai kažkas raudona

Executions skirtukas parodys, kur trūko

Kiekvienas paleidimas - testinis ar suplanuotas - išsaugomas n8n Executions skirtuke. Atsidaręs bet kurį vykdymą matai visą workflow su spalvom: žalia - node'as pavyko, raudona - lūžo. Paspaudęs ant bet kurio node'o matai tikslų jo input ir output JSON būtent tame paleidime - nereikia spėlioti, kur dingo ar sugedo duomenys.

Rask kur lūžo

Raudonas node'as iškart parodo tikslią vietą, be spėliojimo, kuris žingsnis sugadino duomenis.

Matyk tikrus duomenis

Kiekvieno node'o input/output JSON lieka matomas - ne tik klaidos pranešimas, bet ir kas realiai į node'ą atėjo.

Palygink paleidimus

Praeitų vykdymų sąrašas leidžia sugretinti sėkmingą ir nepavykusį paleidimą, kad pastebėtum, kas skiriasi.
